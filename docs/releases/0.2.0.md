# DSIO 0.2.0

DSIO 0.2 is the first release of the generic, project-owned experiment spine validated by
independent supervised, self-supervised, and Kaggle consumer flows.

## What is stable

- `DsioModule` and `DsioDataModule` are the reusable Lightning training boundary.
- Consumer repositories own Prefect DAGs and call DSIO as a versioned library.
- Prefect task attempts are visible top-level MLflow Runs with native dataset, model, metric,
  artifact, and source-Run lineage.
- Training evidence records reconstructible component references and complete execution
  provenance: consumer Git state, dependency lock, command, and DSIO package digest.
- Export reconstructs model and preprocessing components from verified training evidence.
- Governed split generation, windowed and whole-sample datasets, reusable metrics, generic
  PyFunc inference, and evaluation remain project-neutral library components.

## Migration from 0.1

This minor release intentionally removes the alternate framework paths retired by the new
spine. Consumers should make these direct substitutions:

| Removed 0.1 API | 0.2 path |
| --- | --- |
| DSIO runner, `RunConfig`, and task objects | A project-owned Prefect flow composed from DSIO components |
| `dsio.runs` provenance helpers | `dsio.tracking.record_provenance` and automatic execution capture |
| `dsio.eval.contract`, `pool`, and `verdict` | Native MLflow evidence plus `dsio.eval.evaluate`; projects own comparison and promotion policy |
| `dsio.eval.contract.Fold` | `dsio.data.splits.folds.Fold` |
| `dsio.dataset.WindowDataset` | `dsio.data.loading.WindowDataset` |
| `make_loader` and phase-specific dataset aliases | `dsio.data.loading.build_loader` and one phase-neutral dataset constructor |

There is no compatibility shim for these paths. Keeping both would preserve the duplicate
training and evidence protocols this release removes.

## Validation

The release contract includes source and wheel builds, static typing, lint and import
boundaries, isolated installed-wheel consumer flows, generic supervised and self-supervised
flows, and five Kaggle competition workflows covering tabular classification, regression,
computer vision, transfer learning, and submission export.
